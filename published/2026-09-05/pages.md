# GIS становится инфраструктурой для AI-агентов

**Spatial Signals / Пространственный радар · 30 августа - 5 сентября 2026**

Самый интересный сдвиг в GeoAI сейчас происходит не там, где в очередной GIS-продукт добавляют чат.

Меняется сама архитектура работы с пространственными данными.

За последние дни сразу несколько независимых событий показали движение от модели, где человек открывает специализированный GIS-интерфейс и последовательно выполняет операции, к модели, где данные, пространственные вычисления и GIS-функции становятся инструментами AI-агента.

Формируется другой стек:

**пространственные данные -> вычисления -> инструменты / MCP -> агент -> карта / модель -> решение**

Карта при этом никуда не исчезает. Но она постепенно перестает быть обязательной точкой входа во все операции. Иногда карта становится промежуточным состоянием анализа, иногда - способом проверить и объяснить уже полученное решение.

## 1. CARTO превращает GIS-функции в инструменты для агентов

**CARTO** - облачная платформа для пространственной аналитики и работы с геоданными в крупных хранилищах данных.

26 августа компания объявила, что практически все функции платформы теперь могут предоставляться AI-агентам через Model Context Protocol, MCP. MCP - открытый протокол, через который агентные системы подключают внешние инструменты и данные.

Речь идет не только о чтении данных. Агент может работать с картами и аналитическими процессами, обращаться к хранилищам данных, импортировать данные, строить маршруты и изохроны и запускать другие пространственные операции.

**До.** Даже если GIS имел API, пользователь или разработчик должен был заранее понимать, какие операции нужны и в каком порядке их вызвать. AI-помощник чаще оставался дополнительным интерфейсом внутри GIS.

**Теперь.** GIS-функция становится инструментом, который агент может выбрать самостоятельно. Пользователь может сформулировать не последовательность команд, а целевой результат:

> Найди три наиболее перспективных места и объясни выбор.

Агент уже определяет, какие пространственные операции нужны для ответа.

**Следствие.** GIS может работать без жесткой привязки к своему пользовательскому интерфейсу. Карта остается важной, но становится одним из способов взаимодействия с пространственной системой, а не единственным.

Особенно интересна идея разделения рассуждения агента и воспроизводимого вычисления. Агент может сформировать план анализа, но сам расчет выполняется как сохраняемый аналитический процесс. Это уменьшает риск того, что при каждом повторном запросе будет генерироваться новая, немного отличающаяся логика.

Источник: [CARTO - All of CARTO, in every agent](https://www.carto.com/blog/all-of-carto-in-every-agent/)

## 2. Portolan и CARTO SDI: AI-ready становится свойством самих данных

Здесь важно сначала разобраться с двумя новыми названиями.

**Portolan** - открытая спецификация и набор инструментов для публикации пространственных данных как машиночитаемых каталогов в хранилище самого владельца данных. Это не новый формат данных. Portolan задает правила того, как существующие форматы публиковать, документировать, проверять и описывать так, чтобы ими могли пользоваться люди, программы и AI-агенты.

Технически Portolan опирается на STAC для каталога и метаданных и на форматы GeoParquet, COG и PMTiles для прямого доступа к данным.

**CARTO SDI** - коммерческая реализация этой модели от CARTO. Она добавляет к открытому Portolan-каталогу пользовательский каталог данных, интерфейс на естественном языке и контур управления для доступа, качества, версий, статистики использования и монетизации данных.

2 сентября CARTO представила оба направления как новую модель Spatial Data Infrastructure.

Классическая инфраструктура пространственных данных часто устроена примерно так:

**база данных -> GIS-сервер -> WMS/WFS/API -> геопортал -> пользователь**

Publisher должен постоянно поддерживать серверы, API, кеширование и специализированные GIS-сервисы.

Portolan предлагает другую модель:

**GeoParquet / COG / PMTiles -> объектное хранилище -> STAC -> программа или агент**

Данные могут читаться непосредственно из хранилища через современные аналитические движки.

**До.** Пространственный набор данных публиковался прежде всего так, чтобы его нашел и понял человек, обычно GIS-специалист.

**Теперь.** Каталог может сразу содержать структуру данных, описание, географический охват, лицензию, известные ограничения и проверенные примеры запросов для программ и AI-агентов.

Portolan разделяет три точки входа в один набор данных:

- `collection.json` для программ;
- `README.md` для человека;
- `AGENTS.md` для AI-агентов.

**Следствие.** Готовность к работе с AI становится характеристикой самих данных, а не только интерфейса поверх них.

Есть и еще одно следствие. Portolan registry не собирает все данные централизованно. Он объединяет каталоги, которые продолжают храниться у разных владельцев. Агент может найти несколько подходящих источников, проверить их происхождение и объединить их для конкретного анализа.

То есть инфраструктура пространственных данных начинает больше напоминать:

**каталог + метаданные + открытые форматы + хранилище + вычисления**

а не обязательно большой геопортал с собственным серверным стеком.

Источник: [CARTO - Spatial Data Infrastructure, Rebuilt for the Age of AI](https://carto.com/blog/introducing-portolan-and-carto-sdi/)

## 3. PlacePulse добавляет новую операцию для выбора локации - поиск похожих мест

**PlacePulse** - базовая геопространственная модель, созданная CARTO вместе с Applied Geographic Solutions. Она представляет каждую территорию в США как 256-мерное векторное представление места (spatial embedding), описывающее его структуру.

1 сентября CARTO показала, как это можно использовать для выбора новых торговых локаций.

Традиционная модель выбора места обычно начинается с признаков: населения, дохода, плотности, организаций вокруг, конкурентов, транспорта, трафика и других показателей. Затем аналитик решает, какие признаки важнее и как их взвесить.

PlacePulse позволяет начать с другой постановки:

> Где есть территории, похожие на наши самые успешные точки?

Получается цепочка:

**успешные магазины -> зоны вокруг них -> векторные представления -> поиск похожих территорий -> бизнес-ограничения -> кандидаты**

Например, после поиска похожих территорий можно исключить места, расположенные слишком близко к существующим магазинам.

**До.** Аналитик заранее определял, из каких характеристик должна состоять "хорошая локация".

**Теперь.** Можно сначала найти места, структурно похожие на уже успешные, а затем применять дополнительные бизнес-условия.

**Следствие.** В location intelligence появляется новая базовая операция - **поиск пространственно похожих мест**.

Это особенно интересно в сочетании с AI-агентом. Пользователю гораздо естественнее спросить:

> Найди районы, похожие на десять наших лучших локаций, где мы еще не представлены.

чем вручную задавать десятки порогов по населению, доходу и инфраструктуре.

Источник: [CARTO - Building a Retail Fingerprint with PlacePulse Embeddings](https://carto.com/blog/placepulse-retail-fingerprint/)

## 4. Wherobots показывает, насколько проще становится собрать вертикальный spatial-продукт

**Wherobots** - платформа пространственных вычислений вокруг WherobotsDB и Apache Sedona. Она позволяет выполнять Spatial SQL над крупными растровыми и векторными наборами данных и подключать эти операции к AI-инструментам.

31 августа Wherobots опубликовал эксперимент по оценке катастрофических рисков для **2 771 126 зданий в Колорадо**.

В один процесс объединили семь источников данных:

- здания Overture Maps;
- риск природных пожаров USFS;
- наблюдения града NOAA;
- зоны наводнений FEMA;
- показатели торнадо и ветра FEMA;
- земельные участки Regrid;
- пожарные части Overture.

Для каждого здания рассчитывались пять групп риска: пожар, град, наводнение, ветер/торнадо и удаленность от пожарной части.

Техническая цепочка выглядит примерно так:

**растры и векторные данные -> Spatial SQL -> оценки зданий -> H3-агрегация -> PMTiles -> карта**

Данные организованы по уровням Bronze / Silver / Gold в Apache Iceberg. На финальном уровне одна таблица содержит оценки отдельных зданий, другая - агрегированные значения по H3.

WherobotsDB затем сам формирует PMTiles, которые можно показывать в MapLibre без отдельного tile server.

Авторы отдельно делают важную оговорку: это не откалиброванная страховая модель и не система принятия решений о страховании. Это исследовательский прототип, показывающий техническую цепочку.

По утверждению автора, работа заняла примерно один день, а вычисления вместе с AI-токенами обошлись примерно в $300. Эту цифру стоит воспринимать как показатель конкретного эксперимента, а не как отраслевой benchmark.

**До.** Для подобной демонстрации потребовалось бы отдельно организовать обработку растров, пространственные соединения, базу, агрегацию, подготовку тайлов и web-карту.

**Теперь.** Значительная часть цепочки помещается в пространственную вычислительную платформу, а AI-агент помогает собирать и изменять ее.

**Следствие.** Снижается стоимость создания узких пространственных приложений.

Причем страхование - лишь один пример. Та же архитектура применима к оценке паводков, природных пожаров, жары, инфраструктурной устойчивости, пригодности площадок, размещения телеком-объектов или логистических узлов.

Источник: [Wherobots - How to score every building in a state for catastrophe risk](https://wherobots.com/blog/how-to-score-every-building-in-a-state-for-catastrophe-risk/)

## 5. MCP вокруг geospatial превращается из экспериментов в экосистему

**Sparkgeo geo-mcp-servers** - открытый каталог MCP-серверов для геокодирования, маршрутизации, карт, пространственных баз данных, STAC/снимков, настольных GIS и смежных задач. Он важен здесь как индикатор того, что агентные геоинструменты перестают быть одиночными демонстрациями.

На момент финальной проверки каталог Sparkgeo отслеживал **89 MCP-серверов в 11 категориях**.

Отдельный сигнал пришел из QGIS. 3 сентября в официальном каталоге расширений появился **AI GIS AGENT** - плагин для QGIS, который связывает настольную GIS-среду с AI-агентами через MCP, поддерживает запросы на естественном языке, пространственный анализ, управление слоями и выполнение геообработки.

У плагина пока мало установок, поэтому это нельзя использовать как доказательство массового внедрения. Но вместе с MCP-каталогом это полезный сигнал экосистемы.

**До.** Agentic GIS в основном состоял из отдельных интеграций и демонстраций.

**Теперь.** Начинает формироваться слой взаимозаменяемых пространственных инструментов вокруг общего протокола.

**Следствие.** Конкуренция GIS-платформ может постепенно расшириться. Помимо пользовательского интерфейса и собственных аналитических функций важными станут качество инструментов для агентов, семантические описания, метаданные, модель прав доступа, наблюдаемость и способность агента понимать ограничения операции.

Источник: [Sparkgeo - geo-mcp-servers](https://github.com/sparkgeo/geo-mcp-servers), [QGIS Plugin Repository - AI GIS AGENT](https://plugins.qgis.org/plugins/ai_gis_agent/)

## 6. 3D Tiles становится более программируемой инфраструктурой

**3D Tiles** - стандарт OGC для потоковой передачи больших 3D-геоданных: фотограмметрии, зданий, облаков точек, Gaussian splats и других пространственных 3D-наборов.

2 сентября Cesium выпустил первую публичную technology preview векторных тайлов в экосистеме Cesium и 3D Tiles. Это шаг к реализации 3D Tiles 2.0: большие векторные наборы должны получать иерархические уровни детализации, привязку к terrain/3D-геометрии и стилизацию во время выполнения.

Несколькими днями ранее Cesium описал концепцию **составных конвейеров тайлинга (composable tiling pipelines)**. Вместо набора специализированных tiler-инструментов для каждого типа данных предлагается двигаться к модульным переиспользуемым компонентам для фотограмметрии, зданий, облаков точек, Gaussian splats и других типов 3D-данных.

Пока это направление разработки и запрос обратной связи, а не завершенный production-продукт.

**До.** Типичная операция выглядела как "загрузи модель в специальный tiler".

**Теперь.** Она постепенно может превратиться в декларативный конвейер:

**input -> transform -> optimize -> tile -> publish**

**Следствие.** Agentic spatial stack потенциально будет работать не только с 2D-аналитикой. Он сможет создавать и изменять 3D-представления под задачу.

Источник: [Cesium - Vector Tiles: A Technology Preview for Cesium and 3D Tiles](https://cesium.com/blog/), [Cesium - Help Us Shape Composable Tiling Pipelines for Next-Gen Workflows](https://cesium.com/blog/2026/08/27/composable-tiling-pipelines-for-next-gen-workflows/)

## 7. Digital twins получают agent layer - пока больше в research, чем в production

В сентябрьском выпуске *Computers, Environment and Urban Systems* опубликована работа **Towards fully automated city operations: Integrating agentic AI with urban digital twins**. Это исследовательская статья о том, как соединять городские цифровые двойники, AI-агентов и протоколы доступа к инструментам для полуавтоматизированных городских операций.

Авторы предлагают трехслойную AI-архитектуру и концепцию **Urban MCP** для оркестрации городских инструментов. Среди сценариев обсуждаются логистика, оптимизация трафика, управление энергопотреблением зданий и реагирование на бедствия.

Здесь особенно важно не перепутать направление исследований с текущей зрелостью рынка. Работа не доказывает существование полностью autonomous city operations. Она предлагает архитектуру и research agenda.

Но направление логично продолжает эволюцию Digital Twin:

**Twin 1.0** - представление + операционные данные.

**Twin 2.0** - модель состояния + симуляция / what-if.

**Agentic Twin** - данные -> состояние / модель -> симуляция -> агент -> решение -> действие.

Для сравнения: свежий Camden Digital Twin на Cesium используется прежде всего для размещения будущих моделей зданий в городском 3D-контексте и коммуникации planning-сценариев. Это полезная среда цифрового планирования, но в опубликованном case нет признаков полноценного simulation / decision loop.

Такая граница важна: добавление AI-чата к 3D-городу само по себе еще не создает agentic twin.

Источник: [ScienceDirect - Towards fully automated city operations](https://www.sciencedirect.com/science/article/pii/S0198971526000517), [Cesium - Hopeworks Builds Camden Digital Twin with Cesium for Unreal](https://cesium.com/blog/2026/08/31/hopeworks-camden-digital-twin-cesium-for-unreal/)

# Что это значит для рынка

## 1. GIS получает второй интерфейс: не только human-facing, но и agent-facing

CARTO MCP, QGIS agent plugin и растущая MCP-экосистема показывают похожую архитектурную тенденцию. Пространственные функции можно предоставлять независимо от основного пользовательского интерфейса.

Следовательно, GIS-платформа постепенно получает два равноправных интерфейса:

**интерфейс для человека + интерфейс для агента**

Для одних сценариев главным останется карта. Для других пользователь может вообще не открывать традиционный GIS: агент выполнит операции и покажет только итоговую карту, рейтинг или рекомендацию.

## 2. AI-ready spatial stack начинается ниже уровня LLM

Portolan и PlacePulse показывают две разные части будущего стека. Первая делает наборы данных машиночитаемыми и пригодными для прямого доступа из облачного хранилища. Вторая превращает географию в обученные векторные представления.

Поэтому следующая архитектура spatial AI может выглядеть так:

**открытые пространственные форматы -> метаданные / векторные представления -> пространственные вычисления -> инструменты -> агент**

LLM в этой схеме важен, но он не является единственным интеллектуальным компонентом.

## 3. Порог для создания вертикальных spatial-продуктов снижается

Wherobots показывает это на risk-сценарии, PlacePulse - на выборе локаций, Cesium - на конвейерах 3D-данных.

Переиспользуемая инфраструктура начинает заменять часть custom GIS engineering. Это может привести к появлению большего количества специализированных продуктов, которые раньше было слишком дорого делать отдельно.

# Идеи для проверки

## Spatial Risk Engine

Сервис объединяет physical assets с flood/fire/heat/other hazard layers и рассчитывает risk/exposure с пространственным объяснением результата.

**Покупатели:** insurance, banking, real estate, infrastructure.

**Почему сейчас:** вычисления по растровым и векторным данным, открытые datasets и agent tooling заметно уменьшают стоимость первого прототипа.

## Agent-ready Spatial Data Catalog

Каталог данных, где каждый dataset имеет не только описание для человека, но и machine-readable schema, coverage, freshness, licensing и access instructions.

**Покупатели:** public sector, data providers, large enterprises.

**Почему сейчас:** cloud-native SDI и agents превращают метаданные из документации в runtime interface.

## Similarity-based Location Intelligence

Пользователь передает несколько успешных locations, система находит похожие территории и через agent объясняет similarity и применяет дополнительные business constraints.

**Покупатели:** retail, restaurants, banking, logistics, real estate.

**Почему сейчас:** пространственные embeddings добавляют новую abstraction над ручным feature engineering.

# Главный вывод недели

Первый выпуск Spatial Signals получился не про очередную волну "AI for maps".

Сдвиг глубже:

**spatial data и GIS operations постепенно становятся инфраструктурой, которую AI-agent может использовать как часть собственного reasoning process.**

Карта остается.

Но она все чаще становится не началом пространственного рабочего процесса, а его результатом или промежуточным состоянием.

Следующий вопрос - что произойдет, когда к данным, инструментам и агенту добавится полноценный слой симуляции цифрового двойника.
