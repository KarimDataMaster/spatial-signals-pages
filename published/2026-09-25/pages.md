# От карт к агентной инфраструктуре

**Spatial Signals · Пространственный радар · Неделя 39 · 25 сентября 2026**

Еще недавно главный вопрос вокруг GeoAI звучал примерно так: может ли языковая модель нормально работать с картой?

Теперь вопрос меняется.

**Может ли AI сам вызвать нужные пространственные данные и операции, собрать из них решение и вернуть результат пользователю там, где он уже работает?**

События этой недели показывают сразу два взаимосвязанных сдвига.

Первый: карты и GIS перестают быть обязательным отдельным интерфейсом. 2ГИС, Felt и другие платформы превращают поиск мест, маршрутизацию, пространственный анализ и создание карт в инструменты, которые AI-агент может вызывать через MCP.

Второй: поверх этой инфраструктуры появляются специализированные решения для энергетики, недвижимости, геологоразведки, автономной навигации и городского управления.

Новая цепочка постепенно выглядит так:

**пространственные данные → пространственные инструменты → AI-агент → предметная модель → решение**

И это заметно шире, чем просто "чат с картой".

---

## 1. Felt показывает GIS, который пользователь может вообще не открывать

**Felt** — облачная GIS-платформа для анализа, создания и совместной работы с картами. 22 сентября компания [показала совместный эксперимент с Databricks](https://felt.com/blog/gis-agent-databricks-felt-mcp-server), в котором GIS становится частью обычного рабочего процесса пользователя, а не отдельным приложением.

Задача была прикладной: определить энергетическую инфраструктуру Аризоны, находящуюся под угрозой лесных пожаров.

Пользователь сформулировал вопрос в Slack.

Дальше агент в Databricks Agent Bricks самостоятельно нашел нужные таблицы. Отдельный агент выполнил пространственные запросы в Lakebase, серверном PostgreSQL с PostGIS: построил буферы и определил линии электропередачи рядом с активными пожарами.

Через три с половиной минуты появилась живая карта Felt с периметрами пожаров, линиями электропередачи и подстанциями.

Дальше разговор продолжился естественным образом: буфер увеличили до пяти миль, добавили дополнительные данные. В итоге карта содержала четыре слоя, полученные из Databricks.

При этом запросы агента сохранялись как трассировки в Agent Bricks. Результат не нужно было принимать на веру: можно было посмотреть, какие операции реально были выполнены.

### До

Пользователь формулировал задачу, затем GIS-аналитик находил данные, писал пространственный запрос, создавал слои и собирал карту.

### Теперь

Одна агентная цепочка связывает вопрос пользователя, корпоративные данные, PostGIS и конечную карту.

### Следствие

GIS постепенно становится **вычислительной возможностью внутри рабочего процесса**, а не приложением, которое обязательно должен самостоятельно открыть конечный пользователь.

Это не отменяет GIS-эксперта. Наоборот, на человека смещается более важная часть работы: качество исходных данных, корректность пространственных допущений и интерпретация результата.

## 2. 2ГИС открывает геосервисы AI-агентам через MCP

24 сентября 2ГИС выпустил собственный MCP-сервер. Дата релиза и позиционирование подтверждаются [материалом KOD](https://kod.ru/2gis-mcp-server), а технические возможности — [официальной документацией 2ГИС](https://docs.2gis.com/api/ai/mcp-server) и [публичным репозиторием 2gis-mcp](https://github.com/2gis/2gis-mcp).

**MCP, Model Context Protocol** — открытый протокол, который позволяет AI-приложению обнаруживать внешние инструменты и вызывать их по стандартизированному интерфейсу.

Для картографической платформы это означает, что поиск организации, геокодирование или построение маршрута больше не обязательно интегрировать отдельно под каждого AI-ассистента.

2ГИС фактически добавил MCP-слой поверх существующих API.

Сейчас агенту доступны шесть инструментов:

- поиск мест и организаций;
- прямое геокодирование;
- обратное геокодирование;
- построение маршрутов;
- расчет изохрон;
- создание статического изображения карты.

Архитектурно цепочка выглядит просто:

**AI-агент → MCP → API 2ГИС → пространственный результат**

Например, пользователь может попросить ассистента найти круглосуточную аптеку. Агент определяет, что нужен поиск организаций, вызывает соответствующий MCP-инструмент и получает результат из Places API.

Или спрашивает, куда можно добраться за 15 минут от заданной точки. Агент вызывает расчет изохроны.

Важно, что отдельного "AI API" при этом не появляется. Данные, тарифы и ограничения остаются теми же, что при прямом использовании API 2ГИС.

Меняется **способ доступа к продукту**.

### Как это подключается

Сервер опубликован открыто и работает через стандартный транспорт \`stdio\`.

Документация показывает подключение к:

- Claude Desktop;
- LM Studio;
- Cursor;
- VS Code с GitHub Copilot;
- любому другому MCP-совместимому клиенту.

Есть и интересный локальный сценарий: языковая модель может работать на компьютере пользователя через LM Studio, а MCP-сервер будет обращаться наружу только к API 2ГИС.

Если MCP развернут удаленно, его можно подключить по HTTP через шлюз.

То есть картографический API начинает существовать сразу в двух мирах:

**классическая интеграция приложения через API**

и

**вызов пространственной функции непосредственно AI-агентом.**

## Это только 2ГИС или уже рыночный сдвиг?

Именно здесь новость становится значительно интереснее.

2ГИС далеко не единственная картографическая компания, которая идет в эту сторону.

За последний год MCP-слой появился или был заявлен сразу у нескольких крупных геопространственных платформ.

Но глубина доступа у них сильно различается.

| Платформа | Что доступно агенту | Модель |
| --- | --- | --- |
| **2ГИС** | поиск мест и организаций (POI), геокодирование, маршруты, изохроны, статическая карта | геосервисы через локально запускаемый MCP |
| **[Mapbox](https://docs.mapbox.com/location-ai/mcp-servers/mcp-server/)** | поиск, маршруты, матрицы, изохроны, оптимизация, привязка трека к дорожному графу (map matching), геометрические расчеты, карты | расширенный набор геосервисов, локальный или размещенный MCP |
| **[TomTom](https://docs.tomtom.com/tomtom-maps-mcp/documentation/overview)** | поиск, геокодирование, маршруты, оптимизация, трафик, карты | навигация, логистика и дорожный контекст |
| **[Google Maps Platform](https://developers.google.com/maps/architecture/grounding-with-maps-mcp)** | поиск мест, маршруты, погода | полностью управляемый MCP-сервис |
| **[Esri / ArcGIS](https://www.esri.com/arcgis-blog/products/platform/developers/mcp-support-beta-and-arcgis-static-maps-service-in-arcgis-location-platform-release)** | геокодирование, маршрутизация, высоты, статические карты | геосервисы внутри широкой GIS-платформы |
| **[MapQuest](https://developer.mapquest.com/documentation/mcp/)** | поиск, маршруты, трафик, грузовые сценарии | геосервисы через MCP |
| **[Felt](https://www.felt.com/blog/introducing-felt-mcp-server)** | карты, загрузка данных, SQL, пространственный анализ, стили, совместная работа | почти полноценный GIS через MCP |
| **[CARTO](https://carto.com/blog/all-of-carto-in-every-agent/)** | карты, запросы к данным, рабочие процессы, анализ, маршрутизация, изохроны, импорт и администрирование | корпоративная платформа пространственной аналитики через MCP |

Разница здесь важнее самого факта поддержки протокола.

### Mapbox показывает ближайший следующий шаг для 2ГИС

С продуктовой точки зрения самый логичный аналог 2ГИС — **Mapbox**.

У обеих платформ есть картография, поиск, геокодирование, маршрутизация и инструменты для разработчиков.

Но текущий MCP Mapbox предоставляет агенту значительно более широкий набор операций.

Помимо поиска и обычного маршрута доступны:

- матрица времени и расстояний между несколькими точками;
- оптимизация порядка посещения точек;
- изохроны;
- привязка GPS-трека к дорожному графу (map matching);
- расчет расстояний;
- направления между точками;
- центроиды и площади полигонов;
- интерактивное отображение результатов непосредственно в поддерживаемом AI-клиенте.

Отдельно важна модель распространения.

Mapbox можно запустить локально, как и 2ГИС, но компания также предоставляет официальный размещенный MCP-сервис с OAuth.

Пользователь может просто подключить его к совместимому AI-клиенту без самостоятельного обслуживания сервера.

Получается последовательность развития:

**поиск → маршрутизация → пространственные операции → интерактивная визуализация → управление состоянием карты**

2ГИС пока находится ближе к первым ступеням этой цепочки.

### TomTom превращает MCP в автомобильный интерфейс

**TomTom** использует тот же протокол иначе.

Здесь сильнее дорожный и навигационный контекст:

- маршруты с учетом трафика;
- многоточечные поездки;
- оптимизация маршрутов;
- поиск мест;
- геокодирование;
- анализ зон обслуживания;
- дорожные происшествия;
- потоковые данные о трафике;
- статические и интерактивные карты.

В результате агент работает уже не просто с "местом на карте", а с моделью движения автомобиля.

Это важный принцип.

MCP стандартизирует способ вызова инструмента, но не делает продукты одинаковыми.

Именно предметная модель платформы определяет, что агент сможет сделать.

**2ГИС → городские места и навигация**

**TomTom → дорожная сеть, автомобиль и трафик**

**Felt → GIS-анализ**

**CARTO → корпоративная пространственная аналитика**

### Google выбрал противоположный путь: MCP как готовый облачный сервис

У **Google Maps Platform** архитектурная модель отличается.

Google Maps Grounding Lite MCP полностью управляется Google.

Пользователю не нужно скачивать репозиторий, запускать Node.js-процесс или обслуживать MCP самостоятельно.

На момент проверки доступны три основных инструмента:

- поиск мест;
- погода;
- расчет маршрутов.

Это пока более узкий набор возможностей, чем у Mapbox.

Но порог подключения ниже.

Здесь появляется отдельная продуктовая развилка:

**отдать разработчику MCP-сервер**

или

**отдать готовый удаленный MCP-сервис.**

2ГИС сейчас ближе к первой модели.

Mapbox использует обе.

Google делает ставку на вторую.

## Felt и CARTO показывают следующий класс агентного GIS

Сравнивать 2ГИС напрямую с Felt или CARTO не совсем корректно.

Это уже другой уровень абстракции.

2ГИС предоставляет агенту **геосервисы**.

Felt и CARTO постепенно предоставляют агенту **сам GIS**.

Felt еще в апреле запустил MCP примерно с 30 инструментами.

Через него агент может:

- создавать и изменять карты;
- загружать GeoJSON, shapefile, ArcGIS- и WMS-данные;
- получать данные из облачных источников;
- писать SQL к Snowflake, BigQuery, Databricks, PostgreSQL и Redshift;
- выполнять пространственные соединения и фильтрацию;
- создавать новые слои;
- автоматически настраивать стили;
- работать с маршрутами, полигонами, заметками и правами доступа.

CARTO в августе пошла еще дальше.

Через MCP агент получает доступ к картам, рабочим процессам, подключениям к хранилищам данных, геокодированию, маршрутизации, изохронам, импорту данных и административным операциям.

Компания отдельно делает ставку на CARTO Workflows — библиотеку из более чем 200 пространственных компонентов, из которых агент может собирать цепочку анализа: соединения, буферы, обогащение данных, H3-агрегацию и скоринг.

Получаются уже две разные архитектуры.

Первая:

**AI → MCP → отдельные геосервисы API**

Вторая:

**AI → MCP → полноценная среда пространственного анализа**

2ГИС сегодня находится в первой категории.

Felt и CARTO двигаются ко второй.

## А что с российским рынком?

На российском рынке запуск 2ГИС выглядит заметнее.

У **[API Яндекс Карт](https://yandex.ru/maps-api/docs)** уже существуют почти все строительные блоки для похожего сценария:

- интерактивные и статические карты;
- геокодирование;
- поиск организаций;
- матрицы расстояний;
- маршруты;
- изохроны;
- навигационный SDK;
- определение местоположения.

То есть необходимые геосервисы есть.

Однако в публичном каталоге и документации API Яндекс Карт, проверенных для этого выпуска, отдельного официального MCP-сервера для картографических API найти не удалось.

Это не означает, что такой продукт технически невозможен или не разрабатывается. Корректный вывод только один: **публичного официального MCP-интерфейса Яндекс Карт на момент проверки не подтверждено**.

Для NextGIS и других проверенных российских GIS-продуктов также не удалось подтвердить официальный публичный MCP-сервер.

Поэтому 2ГИС становится одним из первых заметных российских примеров, где крупная картографическая платформа официально превращает свои геосервисы в инструменты для внешних AI-агентов.

## До → Теперь → Следствие для картографических платформ

### До

Разработчик AI-продукта выбирал картографический API, изучал его документацию, самостоятельно описывал функции для агента, преобразовывал параметры и ответы и поддерживал интеграционный слой.

Каждый новый картографический поставщик означал отдельную интеграцию.

### Теперь

MCP-клиент может обнаружить стандартизированный набор инструментов и вызвать нужную пространственную операцию.

Модель сама выбирает между поиском места, маршрутом, геокодированием или изохроной в зависимости от запроса пользователя.

### Следствие

Стоимость включения геопространственных функций в AI-продукты снижается.

И меняется сам канал распространения картографического API.

Раньше клиентами платформы были:

**сайт → мобильное приложение → корпоративная система**

Теперь появляется еще один класс:

**AI-агент**

## 3. Сингапур проверяет, могут ли государственные геоданные стать навигационной инфраструктурой для машин

21 сентября **Niantic Spatial** и Singapore Land Authority [объявили о совместном исследовании национальной карты Visual Positioning System](https://nianticspatial.com/blog/singapore-land-authority), VPS, для Сингапура. Это новое продолжение темы Niantic из прошлого выпуска: тогда речь шла о переносе реального объекта в симуляцию, теперь — о национальной инфраструктуре позиционирования для машин.

VPS — технология определения положения и ориентации устройства по изображению камеры и пространственной модели окружающей среды.

Главная деталь здесь не в самом VPS.

Картографическое агентство Сингапура уже располагает национальными аэроснимками и трехмерными облаками точек.

Niantic проверит, можно ли превратить эти существующие государственные данные в инфраструктуру визуального позиционирования без повторного сканирования каждой улицы.

Потенциальные сценарии:

- автономные роботы;
- умная инфраструктура;
- экстренные службы;
- пространственные цифровые приложения.

### До

Для высокоточного визуального позиционирования территорию нужно было предварительно картировать специально для этой задачи.

### Теперь

Проверяется возможность переиспользовать уже существующую национальную геопространственную инфраструктуру.

### Следствие

Аэросъемка и государственные 3D-данные могут получить совершенно новый класс пользователей.

Не людей.

**Машины.**

Это интересное расширение роли национальной пространственной инфраструктуры: от данных для карт и градостроительства к опорному слою физического AI (Physical AI).

## 4. GeoIntelX показывает другой путь: пространственная предметная база знаний

23 сентября **GeoIntelX** [объявила о внедрении платформы GIX в NewMed Energy](https://www.geointelx.com/resources/newmed-partners-with-geointelx-to-accelerate-natural-gas-ep-using-the-gix-ai-platform).

GeoIntelX — специализированная платформа пространственного AI для геологии, добычи полезных ископаемых, энергетики и смежных отраслей.

Здесь проблема совсем другая.

Знания нефтегазовой компании распределены между:

- геологическими материалами;
- историческими исследованиями;
- производственными данными;
- инфраструктурой;
- экологическими материалами;
- нормативными документами;
- корпоративными архивами.

GIX связывает эти источники с пространственными объектами.

После этого специалист может искать информацию не только по ключевым словам, но и по географическому контексту, а также задавать вопросы через AI.

По заявлению NewMed, команда теперь получает ответы на сложные геологические вопросы за минуты вместо дней или недель.

Важно относиться к этой цифре корректно: это заявление самого заказчика, а не независимый сравнительный тест.

Но архитектурный сигнал от этого не меняется.

### До

Корпоративное знание существовало в документах, специализированных системах и отдельных массивах данных.

### Теперь

Оно организуется вокруг физического пространства и становится доступным AI как единая предметная база знаний.

### Следствие

Конкурентным преимуществом вертикального GeoAI становится не только модель.

Им становится **пространственно организованный контекст**.

Универсальная LLM знает, что написано в документе.

Отраслевой GeoAI дополнительно знает:

**к какому физическому объекту относится документ, где этот объект находится и какие другие данные пространственно связаны с ним.**

## 5. Land id применяет ту же модель к недвижимости

21 сентября **Land id** [выпустила The Land id](https://www.prnewswire.com/news-releases/land-id-takes-aim-at-real-estates-demand-for-trusted-answers-with-the-launch-of-its-flagship-ai-insights-product-the-land-id-302884690.html) — AI-продукт для анализа недвижимости, построенный поверх собственного движка Land id Intelligence.

Land id — американская платформа картографирования земельных участков и недвижимости. Компания заявляет более 50 тысяч платных пользователей.

Здесь точкой входа становится адрес.

Система собирает контекст объекта недвижимости из различных источников и помогает интерпретировать его для агента по недвижимости, инвестора или владельца.

Это принципиально отличается от универсального вопроса к карте.

Модель работает внутри конкретной предметной системы:

**участок → объект недвижимости → окружение → данные → интерпретация → решение**

### До

Специалист собирал информацию из отчетов, карт, публичных баз и специализированных сервисов, после чего самостоятельно сводил ее в объяснение.

### Теперь

Пространственный контекст объекта и AI-интерпретация находятся внутри одной вертикальной системы.

### Следствие

Один из наиболее жизнеспособных коммерческих сценариев GeoAI может выглядеть не как универсальный "AI-аналитик карты".

Он может выглядеть как **очень узкий продукт, который знает конкретные пространственные объекты и решения значительно глубже универсального ассистента**.

## 6. Ахмадабад строит пространственную основу для городского цифрового двойника

24 сентября [HDFC SKY сообщил о контракте Genesys International](https://hdfcsky.com/news/genesys-international-secures-rs-283-crore-ahmedabad-project) на создание трехмерной пространственной платформы Ахмадабада в рамках Gujarat Resilient Cities Partnership. Первичный биржевой документ в текущем исследовании не удалось надежно использовать как публичный источник, поэтому этот сигнал помечен как **вторичный**.

Проект охватывает около 625 км² города.

В единую цифровую основу должны войти:

- земельные участки;
- объекты недвижимости;
- дороги;
- водоснабжение;
- канализация;
- ливневая инфраструктура;
- другие наземные и подземные городские объекты.

Здесь особенно важно аккуратно использовать термин "цифровой двойник".

На основании публичного описания проекта подтверждена единая трехмерная пространственная основа и инфраструктурные данные.

Но пока нет достаточных доказательств полноценного цикла:

**состояние → моделирование → решение → автоматическое действие**

Поэтому корректнее относить проект к **основе цифрового двойника / Twin 1.0**, а не к умному или агентному двойнику.

### До

Данные о земле, недвижимости и инженерной инфраструктуре могут существовать в разных ведомственных системах и форматах.

### Теперь

Они собираются в общий пространственный контур.

### Следствие

Ценность цифрового двойника находится не в 3D-картинке.

Она появляется тогда, когда один и тот же физический объект становится общей точкой связи для инженерных, имущественных и управленческих процессов.

# Исследование недели: карту можно использовать как обучающее представление для робота

23 сентября опубликован препринт [NaviScale: Generating Large-Scale Semantic Map Datasets for Object Navigation](https://arxiv.org/abs/2609.27218).

Авторы исследуют ObjectNav — задачу, в которой робот должен найти объект нужного класса в незнакомой среде.

Обычно масштабирование таких экспериментов требует большого количества трехмерных виртуальных помещений.

NaviScale предлагает другой подход: генерировать обучающие данные как семантические карты.

Авторы получили:

- 192 тысячи семантических карт;
- 24 тысячи планировок;
- 12 794 объекта недвижимости.

Подход проверялся на HM3D, Matterport3D и в эксперименте с физическим роботом.

Главная идея здесь шире конкретной модели.

Если часть пространственного обучения можно масштабировать через структурированные карты, GIS получает еще одну роль.

Карта становится не только способом показать пространство человеку.

Она может стать **обучающим представлением пространства для машины**.

# Что это значит для рынка

## 1. Пространственные возможности становятся инфраструктурой для AI

2ГИС и Felt показывают два уровня одного и того же перехода.

2ГИС предоставляет агенту отдельные картографические сервисы.

Felt позволяет агенту выполнять целую GIS-задачу.

Mapbox, TomTom, Google, Esri и CARTO показывают, что движение происходит сразу в нескольких сегментах рынка.

Раньше разработчик встраивал карту в приложение.

Теперь агент **вызывает карту и пространственные операции как инструменты**.

Это фундаментальное изменение интерфейса геопространственной платформы.

---

## 2. Наличие MCP быстро перестанет быть преимуществом само по себе

Когда несколько поставщиков поддерживают один протокол, сам протокол становится инфраструктурой.

Ценность смещается ниже.

Начинают конкурировать:

**Данные.**  
Насколько полны, актуальны и детальны организации, адреса, дороги, здания и другие объекты.

**Пространственные операции.**  
Может ли агент только найти кафе или также выполнить матрицу расстояний, пространственный SQL, оптимизацию, анализ нескольких слоев и моделирование.

**Географический охват.**  
Где именно продукт действительно имеет сильные данные.

**Визуальная обратная связь.**  
Получает ли пользователь просто текст и JSON или полноценную интерактивную карту.

**Управление и безопасность.**  
Какие операции агенту разрешены, как управляются права и сохраняется ли история действий.

**Стоимость вызовов.**  
Агент может выполнить несколько инструментов последовательно, поэтому экономика API становится еще важнее.

В результате вопрос "есть ли у продукта MCP?" достаточно быстро перестанет быть интересным.

Гораздо важнее:

**что полезного агент реально может через него сделать?**

---

## 3. Поверх этой инфраструктуры начинают расти вертикальные GeoAI-продукты

GeoIntelX работает с нефтегазовой геологией.

Land id — с недвижимостью.

Niantic — с навигацией машин.

Felt показывает энергетический риск.

Ахмадабад строит единую пространственную модель городской инфраструктуры.

Во всех этих случаях карта остается важной частью системы.

Но сама карта уже не является продуктом.

Продукт — это:

**предметный вопрос → пространственный контекст → специализированные данные → операции → решение**

Поэтому следующим конкурентным преимуществом GeoAI может стать не универсальность модели, а качество **пространственной модели конкретной предметной области**.

# Практический вывод

При проектировании GeoAI-продукта полезно разделять три уровня.

### 1. Пространственная инфраструктура

Какие базовые функции можно надежно дать агенту:

- поиск;
- геокодирование;
- маршрутизация;
- изохроны;
- пространственные запросы;
- пользовательские данные;
- визуализация.

### 2. Предметная модель

Какие реальные объекты понимает система:

- магазин;
- участок;
- месторождение;
- линия электропередачи;
- объект недвижимости;
- дорога;
- инженерная сеть.

И какие связи между ними важны.

### 3. Решение

Какой результат нужен пользователю:

- выбрать участок;
- определить риск;
- найти инфраструктуру;
- построить маршрут;
- проверить гипотезу;
- создать полевую задачу;
- принять инвестиционное решение.

Слабый AI-продукт обычно начинается с вопроса:

**"Как добавить чат в карту?"**

Более сильный начинается с другого:

**"Какое решение сегодня требует пространственных данных и нескольких ручных действий, и какую часть этой цепочки агент может выполнить сам?"**

---

# Что проверить бизнесу / гипотезы

### 1. Проверить GIS без GIS-интерфейса

Выбрать реальную пространственную задачу и дать бизнес-пользователю решить ее через диалог с агентом.

Сравнить с обычной цепочкой:

**запрос → аналитик → GIS → результат**

по времени, количеству ручных действий и необходимости участия специалиста.

### 2. Проверить глубину инструментов агента

Разложить один отраслевой сценарий на операции и посмотреть, где заканчивается текущий набор инструментов:

**поиск → маршрут → изохрона → агрегация данных → сравнение территорий → карта → действие**

Это быстро покажет разницу между "MCP для API" и полноценным агентным GIS.

### 3. Проверить ценность пространственной предметной модели

Сравнить ответы обычного корпоративного AI с системой, где документы и данные заранее связаны с адресами, участками, зданиями или другими физическими объектами.

Если пространственное связывание существенно повышает качество ответа, главным активом продукта становится уже не только модель, но и организованный вокруг пространства предметный контекст.
